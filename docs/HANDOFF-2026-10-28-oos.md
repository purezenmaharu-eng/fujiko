# 引き継ぎメモ: 期間分割と改善案の試験(2026-10-28)

## 結論
- 改善案A(地合いフィルタ)・C1・C2(出口ルール変更)は**不採用**。
- 案B(King に Fスコア5点以上の関門=次点を監視に含める)は**候補**。ただし**本番には入れない**。
- 結果ページ: `docs/walkforward_oos.html`(`python walkforward.py --cache-only --partial --end 2026-10-14 --oos`)。

## 理由
- 5点を選んだのは通期の表を見たあとなので、「試す期間」が純粋な検証になっていない。
- 本番はすでに 6点以上=合格、5点=次点 としている。
- 銘柄は171銘柄のみ + 生き残りバイアス(今の上場銘柄だけ)。成績は良めに出る。

## 数字(試す期間 2025-01〜2026-10。騰落率 / 最大DD / シャープ)
- King 現状: +53.5% / -15.6% / 1.51
- King 案B: +83.6% / -15.1% / 1.99
- 日経平均: +73.0% / -22.3% / 1.35

## 再検証の予定: 2027-01 以降(約3か月分のデータが増えたあと)
1. 株価キャッシュを新しく作り直す。
2. `python walkforward.py --partial --oos` を実行する。
3. 「新しく増えた期間だけ」で King の現状と案B を比べる。
4. 合格条件: 新しい期間で、騰落率とシャープが現状以上、かつ最大DDが悪化しないこと。
5. 通ったら、次点(5点)を King の監視に含める変更を**別のPR**で検討する。

## 再現の条件
- baseline(関門なし)は `prices_2026-10-14.pkl`(172銘柄・対象171)で、Ace +217.7%・King +105.5%・1306 +127.3% と一致することを確認済み。
- `--end` は `prices_<日付>.pkl` のファイル名を指す(日付そのものではない)。
- 決算(EDINET DB)のキャッシュは171銘柄中15銘柄が未取得のため `--partial` が必要(未取得は「データ不足」扱い)。
- `--oos` は日経平均(^N225)をyfinanceから1回取得し `.cache_wf/n225_<end>.pkl` に保存する(以降はキャッシュ)。

## 比較の基準に注意
- 本番の監視は6点以上なので、本番相当の基準は「Fスコア6点以上」(King 通期 +102.5%・シャープ 1.13)。
- 「関門なし」(King 通期 +105.5%・シャープ 1.04)との比較だけで案Bの良さを判断しない。
